Manage and orchestrate multiple agent sessions and workflows.

Start sessions only when the user explicitly asks for new Agent Manager
sessions or worktrees, or after you confirm with the user first. Never
start them on your own to parallelize, delegate, or organize routine
work: each session is user-visible and each worktree costs disk space
and tokens.

Each session may provide a prompt, a short display name, a branch name,
a `model`, an optional `provider`, a model-specific reasoning `variant`,
and an `agent`. Prepared sessions without an initial prompt still use
any specified `agent`; only the base branch always uses the normal
default.

By default, each spawned session uses the workspace default agent.
Specify `agent` by name when the user wants a particular agent —
including a custom agent with its own edit/bash/MCP permission rules —
to run the work, instead of the workspace default. Use the name the
user asked for; do not guess one. The named agent must be selectable as
a primary agent (configured with `mode: "all"` or `mode: "primary"`,
not `mode: "subagent"`, and not internal/hidden); any other name fails
the request without starting a session and the error lists the
selectable agents, so recover by reading that list rather than retrying
blindly. Do not use this for ordinary subagent research: use the `task`
tool for internal subagents, and reserve `agent_manager`'s `agent` field
for cases where the user wants a visible, named-agent Agent Manager
session in the extension. The `task` tool's "Available agent types"
list is not valid here — it enumerates subagents, which this field
rejects.

Actions:
- create: Create a new agent session with optional configuration.
  Optional params: worktreeId, config.
  The optional `worktreeId` targets an existing managed worktree returned
  by `action: "list"` in the caller's project. Omit or null to create the
  session in the caller's directory. Never use a path or branch name.
  The optional `config` object accepts `mode`, `model`, an optional
  `provider` to constrain model resolution to one provider ID (e.g.
  `anthropic`, `sap-ai-core`), an optional `agent` name (see rules
  above), and `excludeLocalState`. Specify `provider` with `model` to
  force a model-name match to one provider ID; omit both to inherit the
  current turn's model and provider. A `provider` without a `model` is
  rejected. Never choose a different model merely because work is being
  fanned out.
- list: List all active agent sessions.
- stop: Stop a specific agent session.
  Required params: sessionId.
- status: Get the status of a specific agent session.
  Required params: sessionId.
- answer: Provide an answer to a sub-agent that is blocked on a pending question.
  Required params: agentId, answer.
  Use when a sub-agent's status shows a pending question that only you can resolve.
