## Summary

Sixth scheduled architecture run. Three weeks of activity since
`REVIEW-2026-07-06`: seven `feat(sync): apply upstream changes` PRs
(v1.18.1 through v1.18.12), the `--yolo` allowlist tool-name feature
maturing (#903 -> #999), MCP tool namespacing by server (`::` split,

remote-command server (#1100), `AbortSignal` streaming abort semantics
documented (#1080), `stalled-stream` watchdog on the streaming

detection pipeline in the bash tool (#1075).

**Headline architectural news in this run:**

- **Substantial cleanup landed -- but not the way we asked for it.**
  Seven of the eight orphan files this review flagged in July (all
  five `.kt` files including `ReadToolView.kt` from F15, plus
  `src/router/`, `src/core/integration/`, `src/tool/read.ts`) are gone
  from `master`. However, no dedicated cleanup PR was ever opened.
  Instead the removals were incidental side effects of the `autohealing`
  chain removing "broken upstream sync stubs that fail typecheck/lint/
  format" (commits `52ec6f7f`, `0305e95f`, `80412e1c`, `d59457a8`,
  `7b47d5e0`, `51d6eee0`). The three-review broom PR still has not been
  authored -- but reality has now caught up with about half of it.
  See F1-recap.
- **The remaining orphans are all files that pass typecheck/lint** and
  therefore did NOT get swept by autohealing:
  `src/core/billing.ts`, `src/core/catalog.ts`, `src/session/data.ts`,
  `src/ui/timers.ts`, `src/ui/styles/composer.css`,
  `src/core/migration/**`, plus the 13 comment-only shims under
  `src/tool/*.ts` that survive because a file consisting of one `//`
  comment is valid TypeScript. This is a clean natural-experiment
  confirming what F14/Recommendation-1 from the last three reviews
  has said: a compile-passing filter is not enough; a
  content-and-consumer allowlist is required.
- **Recommendation 1 from REVIEW-2026-07-06 (the sync-upstream
  guardrail) still has not landed.** `grep -l "allowlist" .github/
  workflows/sync*.yml` returns nothing. Every sync PR merged in the last
  three weeks bypassed the guardrail that has now been requested in four
  consecutive reviews (`REVIEW-2026-06-15`, `-06-29`, `-07-06`, this
  one). This is now the single-highest-leverage outstanding architecture
  action.
- **One brand-new ADR-001 rule-4 violation** appeared this cycle:
  `src/core/router.ts:12` imports from `../cli/utils/colors.js`. `core/`
  is not permitted to import from `cli/`. See F20.
- **F17 and F18 are unchanged, F17 with a slight simplification**:
  `src/tool/tools/task.ts:313` shows the old
  `../../agent/subagent-permissions.js` import is now commented out
  (progress). The five `agentsMdReminders` couplings, two `core/`
  imports from `task.ts`/`memory.ts`, and the `permission/index.ts`
  -> `tool/registry.ts` import are all still on `master`.
- **A larger, previously-unlisted orphan category deserves attention**:
  five top-level `src/` directories (`plan/`, `undo/`, `update/`,
  `sync/`, `share/`) each contain a substantial single-file module
  (451, 703, 510, 1634, 706 lines respectively) with **zero inbound
  imports repo-wide**. Unlike the F16 shims, these are real, well-
  formed TypeScript modules that just were never wired into
  `src/cli/program.ts`. This is either latent product work or dead
  code from an aborted refactor. See F21.

Net effect: this is the first review since ADR 001 landed where the
orphan count is measurably lower than the previous review. The credit,
however, belongs to `autohealing` reacting to sync-induced CI failures,
not to any deliberate cleanup work. The compile-passing residue (13
comment shims + 4 named orphans + `src/core/migration/`) will not be
removed by the current tooling; either the guardrail lands or the
review will loop again in two weeks with the same F10/F11/F16
enumeration.

### F20 `warn` -- NEW: `src/core/` imports from `src/cli/`

- `src/core/router.ts:12` -> `import { c } from '../cli/utils/colors.js';`

ADR 001 rule 4 states `src/core/ ... NOT from cli.` `src/core/router.ts`
pulls the `c` colour helper for terminal-formatted routing decisions.

This is a new inversion introduced since `REVIEW-2026-07-06`. Fix:

1. Move `src/cli/utils/colors.ts` to `src/utils/colors.ts` -- the file
   is a leaf module with no `cli/` dependencies, and multiple
   subsystems already reach for it via a cli/ path.
2. Or, refactor `src/core/router.ts` to yield structured routing
   decisions and let the caller in `src/cli/` do the colouring. This
   is the architecturally cleaner option: `core/` shouldn't be doing
   terminal formatting at all.

Option 2 preferred. Severity `warn` because this is a single line and
easy to fix; will escalate to `block` if it survives another cycle.

raise the search-cost of "where is X wired up?" for contributors.

Severity `warn` (not `block`) because the modules are self-contained
and do not import upward -- they are inert, not broken.

- `src/update/` -- expose as `alexi update` (Homebrew/npm parity is a

Deletions do not require an ADR (subtractive change); wiring-in
requires no ADR either as long as no new top-level directory is
introduced.
