`src/core/session/` was introduced by

   The upstream sync channel keeps pre-landing modules with no
   caller. Some (like `src/plan/`) eventually get wired; most
   (like `src/undo/`, `src/update/`, `src/share/`, `src/sync/`)
   still have not, four cycles later.

Severity `warn` -- pattern-matches F21. Disposition proposed in
Recommendation 3.

### F27 `warn` -- NEW: `src/core/kilocode/` sub-directory collides with top-level `src/kilocode/`

`src/core/kilocode/` landed via the 2026-08-25 sync PR
(`aa8be6ef`). Two files:

- `src/core/kilocode/fff.ts` -- 4307 B. Provides `allowed(dir)`
  which rejects filesystem-root / home-directory indexing. **Is
  wired** via `src/core/filesystem/watcher.ts:35`
  (`import { allowed } from '../kilocode/fff.js';`). Docstring
  cites kilocode upstream `6e05f48fb`, `08467dba4`, `b0dbd398a`.
- `src/core/kilocode/zero-id.ts` -- 1464 B. Provides `zeroID(...)`
  composite-key builder using `\0` as separator. **Zero external
  references** (`grep -rn "kilocode/zero-id" src/` returns only
  its own declaration).

Three architectural concerns:

1. **Filename `fff.ts` is opaque garbage.** No reader can guess
   what `fff` means. The docstring explicitly names it "Filesystem
   root / home directory indexing guard". A three-letter mystery
   filename in `src/core/kilocode/` is a maintenance hazard --
   grep-friendly names (`filesystem-root-guard.ts` or
   `indexing-guard.ts`) belong here.
2. **Directory-name collision with top-level `src/kilocode/`**
   (the F24 subject). We now have `src/kilocode/sandbox/git.ts`
   AND `src/core/kilocode/fff.ts` and `zero-id.ts`. Two
   different `kilocode/` buckets at two different layers, both
   used as "code ported verbatim from upstream". This is
   incoherent as a layering rule; either kilocode/ is a shared
   layer or it is a per-package "here be dragons" bucket, but
   it cannot be both.
3. **`zero-id.ts` is zero-inbound** and would collide, if wired,
   with any hypothetical future call site -- the same F25 /
   F26 problem.

Severity `warn`. Disposition: bundled into ADR 006 (F24). The ADR
must resolve BOTH the top-level `src/kilocode/` AND the nested
`src/core/kilocode/` -- pick one home for "upstream-ported
utilities" (options: (a) accept top-level as durable, delete the
nested one and move its contents into top-level; (b) delete the
top-level and standardize on nested kilocode/ per parent layer;
(c) both go away, files are moved to their natural homes
`src/tool/sandbox/` and `src/core/filesystem/`). Rename `fff.ts`
regardless of the outcome.
