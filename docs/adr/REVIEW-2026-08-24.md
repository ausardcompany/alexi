### F24 `warn` -- NEW top-level `src/kilocode/` added without an ADR

`src/kilocode/sandbox/git.ts` (95 lines) landed via the 2026-08-19
upstream sync (`b0910964`). It provides `requiresSandboxEscalation`
and `isGitWrite` for `src/tool/tools/shell.ts:18` to consult when
`ALEXI_SANDBOX=1`. This IS wired -- unlike F21 -- so the module is
architecturally justified.

Two ADR-001 concerns:

1. **Rule 3 (new top-level `src/<name>/`) was tripped without an
   ADR.** ADR 001 requires that any new top-level module directory
   is introduced by an ADR that names the layer it belongs to and
   the imports it may consume. There is no ADR under `docs/adr/`
   naming `kilocode`. `docs/ARCHITECTURE.md:1631-1637` mentions
   the module but the "Directory Structure" section
   (`docs/ARCHITECTURE.md:1643-1690`) does not list it -- see the
   docs-drift note in Recommendation 3.

2. **Layer placement is ambiguous.** `kilocode/` currently contains
   pure classification logic (no I/O), consumed by `src/tool/`.
   Two structurally cleaner options: (a) move to
   `src/tool/sandbox/git.ts` (co-locate with the sole caller); or
   (b) move to `src/utils/sandbox/git.ts` (treat as a shared
   pure-function utility). A new top-level `src/kilocode/` bucket
   for "code ported verbatim from upstream kilocode" is not a
   layering justification -- upstream provenance already lives in
   `docs/ARCHITECTURE.md` prose and `feat(sync)` commit history.
   Precedent-worry: if `kilocode/` is accepted as a valid
   top-level bucket, the next four upstream ports will land under
   `src/kilocode/<something>/` and we get another F21-style
   dumping ground.

Severity `warn` (module is load-bearing, so this is not `block`).
Recommended disposition: file ADR 006 that EITHER accepts
`src/kilocode/` as a durable top-level with a scoped charter
("upstream-ported classification utilities, no I/O, consumed by
`src/tool/` only"), OR schedules a mechanical rename to
`src/tool/sandbox/` or `src/utils/sandbox/`. This is Recommendation
1's exact use case: a sync-allowlist guardrail would have flagged
`b0910964` at PR time.
