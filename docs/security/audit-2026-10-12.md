## Critical (block)

### C1 -- `--yolo` deny-list bypass: case sensitivity + missing dot-escape + no SAP token coverage (UNRESOLVED CARRY-OVER, week 7 -- ESCALATED `#2001`)

- Files:
  - `src/permission/allow-everything.ts:53-56` -- `matchesPattern()`
    naive glob-to-regex converter (verbatim unchanged from 2026-05-25
    commit `099dfc63`).
  - `src/permission/index.ts:375-393` -- `getAllowEverythingDelegate()`
    seeds excludes from the `deny-secrets` rule.
  - `src/permission/index.ts:387` -- belt-and-braces list is still
    `**/.ssh/**`, `~/.ssh/**` only. No SAP token coverage.
- Bug (unchanged for six consecutive audits):
  `new RegExp(pattern.replace(/\*/g, '.*'))` is case-sensitive,
  does not anchor with `^` / `$`, and does not escape the `.`
  metacharacter. Three concrete bypasses in `--yolo` mode:
  1. Case-only variants of `**/.env` (`.ENV`, `.Env`,
     `AICORE_SERVICE_KEY.JSON`) do not match.
  2. `**/.env.*` expands to `.*/.env..*` (unescaped dot) so a
     co-located `foo.env` / `dev.env.local` variant slips through if
     renamed.
  3. `**/*credential*` / `**/*secret*` are literal substring
     keywords only -- they miss `AICORE_SERVICE_KEY*`,
     `ghp_*` / `github_pat_*`, `NPM_TOKEN`, and `SAP_PROXY_*`. The
     belt-and-braces `**/.ssh/**` at `src/permission/index.ts:387`
     catches SSH keys, but no equivalent exists for the SAP token
     family.
- Severity: `block`. `--yolo` is wired into every agent workflow via
  `--auto` / `--dangerously-skip-permissions` (`AGENTS.md` "Tool
  harness"). A prompt injection that convinces the agent to read
  `AICORE_SERVICE_KEY.json` in `--yolo` mode succeeds today.
- **Action this run:** escalated to issue `#2001` with the full fix
  blueprint, per the 2026-09-28 R9 carry-over policy. `role-security`
  does not implement code fixes under `src/permission/`; `role-
  engineering` owns the implementation.

### C2 -- `xlsx@0.18.5` prototype pollution + ReDoS, no upstream fix (RUNTIME REACHABLE, UNRESOLVED CARRY-OVER)

- Advisories via `npm audit`:
  - `Prototype Pollution in sheetJS` (`GHSA-4r6h-8v6p-xvw6`, CVSS 7.8).
  - `SheetJS Regular Expression Denial of Service (ReDoS)`
    (`GHSA-5pgg-2g8v-p4x9`, CVSS 7.5).
- `range: "*"`, `fixAvailable: false` on `npm audit`. SheetJS has
  moved fixes to a paid-only channel (`https://cdn.sheetjs.com/`).
- Reachability (unchanged from 2026-10-05): dynamic import at
  `src/tool/tools/read-office.ts:181` with the `readFile(filePath,
  { cellDates: true, cellNF: true })` call at `:189`. User-supplied
  paths reach this through the `read` tool. A malicious `.xlsx`
  committed to any repo the agent reads can trigger either CVE on the
  runner.
- Severity: `block`. Promoted to critical in 2026-10-05 because of
  runtime reachability.
- Recommended fix (owner: `role-engineering`):
  - Short term: guard `xlsx.readFile` at
    `src/tool/tools/read-office.ts:189` with a size cap AND a
    permission confirmation. Size cap alone will not prevent the
    prototype-pollution CVE (small inputs still fire it).
  - Preferred: replace with `exceljs@^4.4.0` (active security
    channel, similar `readFile` + `getWorksheet(idx).eachRow` API).
    The `read-office.ts` call site reads cells only, so the migration
    surface is small (`worksheetToCsvRows` at `:231`).
  - Fallback: feature-flag `.xlsx` extraction off by default in
    `isOfficeDocument()` at `src/tool/tools/read-office.ts:36` until
    `exceljs` lands.

### H7 -- `jks-js` + `node-forge` RSA PKCS#1 v1.5 signature acceptance (NEW)

- Chain: `@sap-cloud-sdk/connectivity -> jks-js -> node-forge`
  (confirmed via `npm audit --omit=dev --json`).
- Advisory: `node-forge: RSA PKCS#1 v1.5 signature verification
  accepts extra nested DigestAlgorithm elements`. Together with the
  entire `jks-js` tree being pulled in via the SAP Cloud SDK's JKS
  (Java KeyStore) parser, this exposes an incorrect signature
  verification path if an operator wires a JKS trust store through
  the SAP Cloud SDK.
- Severity: `warn`. Alexi does not call `jks-js` directly; the
  surface opens only when `@sap-cloud-sdk/connectivity` consumes a
  trust store from an SAP destination configuration (code path:
  `node_modules/@sap-cloud-sdk/connectivity/dist/scp-cf/certificate.js`).
  Default local runs do not touch it.
- Recommended action: `npm update @sap-cloud-sdk/connectivity`
  (`fixAvailable: true` per audit). Owner: `role-security`
  (Dependabot triage) -- hold for the SAP Cloud SDK's own release
  rather than forcing a nested bump that could desync the `@sap-ai-sdk/*`
  tree.
