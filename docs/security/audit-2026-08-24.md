## Critical (block)

### C1 -- `--yolo` deny-list bypass: case sensitivity + missing dot-suffix + no keyword coverage

- Files:
  - `src/permission/allow-everything.ts:53-56` -- `matchesPattern()`
    naive glob-to-regex converter.
  - `src/permission/index.ts:283-295` -- delegate builder that seeds
    excludes from the `deny-secrets` rule.
  - `src/permission/index.ts:869-876` -- `deny-secrets` patterns:
    `**/.env`, `**/.env.*`, `**/secrets.*`, `**/*credential*`,
    `**/*secret*`, plus belt-and-braces `**/.ssh/**`, `~/.ssh/**`.
- Bug: `matchesPattern` does `new RegExp(pattern.replace(/\*/g, '.*'))`.
  This is case-sensitive by default and does not anchor. On Linux (the
  actual runtime for `alexi-bot`) it produces three bypasses in
  `--yolo` mode:
  1. **Case bypass.** A resource named `/repo/mySecret.txt`,
     `/repo/MYSECRET.pem`, `/repo/Credentials.json`, or
     `/home/alice/.SSH/id_rsa` does NOT match the exclude patterns and
     is auto-allowed. Verified locally by running the exact
     `matchesPattern` implementation against these paths -- all seven
     patterns miss.
  2. **Missing-extension bypass.** `**/secrets.*` requires a dot
     followed by any character. `/etc/secrets` (bare, no extension)
     does not match `secrets.*`; it happens to be caught by
     `**/*secret*` today, but the pattern set has no defense-in-depth
     if `deny-secrets` is edited to remove `**/*secret*` and drop the
     wildcard.
  3. **Keyword blindness.** There is NO exclude pattern covering
     `AICORE_SERVICE_KEY`, `NPM_TOKEN`, `GH_PAT`, `SAP_PROXY_*`, or
     bare `*.pem` / `*.key` files. A user who invokes
     `alexi chat --yolo --message "read AICORE_SERVICE_KEY.json"` gets
     auto-approved on that path. The tests in
     `src/permission/allow-everything.test.ts:55-89` only check
     `/repo/.env`, `/repo/secrets.json`, `/home/alice/.ssh/id_rsa` --
     all lowercase, all dot-extension -- so the test suite is blind to
     these gaps.
- Why this is `block`:
  - `--yolo` skips the `PermissionRequested` bus event entirely
    (`allow-everything.test.ts:32-53` confirms zero events fire), so
    there is no human-in-the-loop check to catch a misclassified
    resource.
  - The baseline system prompt explicitly bans weakening the permission
    system without an ADR. Wiring `AllowEverythingPermission` behind
    `--yolo` with a naive `.replace('*', '.*')` glob engine constitutes
    an unaudited relaxation.
  - AGENTS.md rule: `--dangerously-skip-permissions` stays opt-in only.
    The flag is opt-in, but its deny list is misconfigured, which
    defeats the purpose of the opt-out.
- Recommended remediation (tight, mechanical):
  1. Replace `matchesPattern` with a proper micromatch / minimatch
     call (already an indirect dep via glob), with the `nocase: true`
     option enabled.
  2. Extend the `deny-secrets` `paths` array (or add a separate
     `--yolo`-only deny list in `index.ts:278`) to include:
     `**/*.pem`, `**/*.key`, `**/*.p12`, `**/*.pfx`,
     `**/AICORE_SERVICE_KEY*`, `**/NPM_TOKEN*`, `**/GH_PAT*`,
     `**/SAP_PROXY_*`, `**/id_rsa*`, `**/id_ed25519*`, `**/.aws/**`,
     `**/.kube/**`, `**/.docker/config.json`.
  3. Add regression tests in `allow-everything.test.ts` for each of
     the three bypass classes: (a) mixed-case, (b) missing extension,
     (c) new keyword coverage. Each test must assert
     `result.granted === false` under `setPermissionMode('auto')`.
  4. Add a doc-only note in `docs/permission-system.md` that `--yolo`
     is a scoped-safe mode, not a full bypass, and enumerate the
     exclude classes so future PRs cannot silently narrow it.

### C2 -- `xlsx@0.18.5` still has Prototype Pollution + ReDoS, still no upstream fix

- File: `package.json:60` (direct dependency, pinned `^0.18.5`).
- Advisories:
  - GHSA-4r6h-8v6p-xvw6 (Prototype Pollution in SheetJS).
  - GHSA-5pgg-2g8v-p4x9 (SheetJS ReDoS).
- `fixAvailable: false` per `npm audit --omit=dev --json`.
- Used by: `src/tool/tools/read-office.ts` (XLSX-to-CSV preview in the
  `read` tool). Reachable from any agent that reads `.xlsx`/`.xlsm`
  files supplied by the user or an MCP server.
- Status: unchanged from 2026-06-22 audit C1. Kept at `block`
  severity because the `read` tool is invoked by automated agents
  without per-call user approval, and `--yolo` mode (see C1) now

     or a thin in-house ZIP+XML CSV extractor for the small surface we
     use (`readFile`, `utils.sheet_to_csv`).
  Track as a `security`-labelled issue -- non-mechanical, needs
  `role-architecture` sign-off on the office-tool API change.

### W3 -- `ExternalDirectoryPermission.evaluate()` still uses naive `startsWith()` (UNCHANGED from 2026-06-22 W3)

- File: `src/permission/external-directory.ts:43`.
- Issue 1: `normalizedRequest.startsWith(normalizedConfig)` has no path
  separator boundary check. Allowing `/srv/alexi-data` would also
  authorise `/srv/alexi-data-evil/secret`.
- Issue 2: `normalizePath()` (line 21) lowercases the path. On Linux
  (case-sensitive FS) this destroys case fidelity -- allowlist for
  `/Project/Foo` would also accept `/project/FOO`.
- The correct pattern lives in `src/utils/filesystem.ts:16`
  (`containsPath`): resolves both paths then checks the remainder
  starts with `/`.
- **Two months of no fix** despite prior audit call-out. Escalate:
  open a `security`-labelled issue and either assign or close as
  "won't fix, deprecate `ExternalDirectoryPermission`". If the Ask-mode
  code path is not currently reachable, the honest fix is to delete
  the module rather than let it accumulate dust with a known bypass.
- Severity `warn` (not `block`) only because `PermissionManager` uses
  `containsPath` correctly via `isExternalPath()`
  (`src/permission/index.ts:369`) and no caller currently relies on
  `ExternalDirectoryPermission` for trust decisions.

### W4 -- `release.yml` still runs `npm ci` and `npm publish` without `--ignore-scripts` (UNCHANGED from 2026-06-22 W4)

- File: `.github/workflows/release.yml:87,93,96`.
- The `publish-npm` job exports `NODE_AUTH_TOKEN=${{ secrets.NPM_TOKEN }}`
  (line 95) and runs `npm ci` (line 87) without `--ignore-scripts`. Any
  compromised transitive dep's `postinstall` would execute with the
  npm token in scope and could publish a malicious replacement package.
- `npm publish --access public` (line 93) also has `continue-on-error: true`
  (line 96), which silently masks publish failures and can hide token
  scope / MFA misconfiguration.
- Recommended:
  - Add `--ignore-scripts` to both `npm ci` and `npm publish` in the
    `publish-npm` job. Keep scripts enabled in the earlier build job;
    it does not hold `NPM_TOKEN`.
  - Remove `continue-on-error: true` from the publish step.
- Two-month regression: no PR touched this file since the last audit.

### W5 -- `image_gen` tool writes to `$TMPDIR/alexi-images` by default; user-controllable via `outputPath`

- File: `src/tool/tools/image-gen.ts:305-309, 337-338`.
- New tool wired end-to-end in commit `f7817e11` (2026-08-23).
- Positive: permission block is correctly declared, mapping the tool
  to `action: 'write'` on `params.outputPath ?? defaultImageOutputDir()`.
- Concern 1: `params.outputPath` is a free-form string. There is no
  validation that it stays inside the workdir or matches
  `containsPath(cwd, outputPath)`. An agent can be prompt-injected via
  a poisoned `image_gen` call from a malicious MCP server description
  into writing under `~/.ssh/`, `~/.aws/`, or `/etc/`. The permission
  check will fire, but under `--yolo` (C1) it is short-circuited, so
  the deny list must catch the traversal. `**/.ssh/**` catches
  `~/.ssh/`; `**/.aws/**` is NOT currently in the deny list (see C1).
- Concern 2: `URL` payloads returned by the model are surfaced verbatim
  in the tool result (`entry.url`). If the caller / TUI eagerly fetches
  them, the fetch bypasses network permissions. Not exploitable today
  because the fetch is caller-side, but worth a comment.
- Recommended:
  1. In `image-gen.ts` `execute()`, add a
     `containsPath(process.cwd(), outputDir)` check before
     `fs.mkdir`. If the check fails, require explicit permission via
     the `write` bucket rather than only requesting it on the resource
     string (the current permission wiring can be over-permissive when
     `outputPath` points at an already-writable ancestor).
  2. Cap `entry.url.length` at 4096 and reject `javascript:` /
     `data:` / `file:` schemes at the tool boundary. Provider is
     trusted, but defense-in-depth is cheap.
- Severity `warn`: exploitation requires either `--yolo` mode or a
  compromised MCP tool description. C1 makes the first vector real.

### W6 -- `pull_request_target` workflows: `head.ref` still interpolated into shell (UNCHANGED from 2026-06-22 W6)

- Files: `.github/workflows/on-release-merge.yml:4`,
  `.github/workflows/update-homebrew.yml:9`.
- Both pin `ref: master` on checkout and gate on
  `pull_request.merged == true` -- good.
- `on-release-merge.yml:27-29` still derives
  `VERSION=${BRANCH#release/}` from `head.ref` via expression
  substitution rather than through an env block. Branch names cannot
  include `|`, but `;` and backticks are still legal in git ref names.
  The `startsWith('release/')` filter plus PR-merge gate makes
  exploitation require admin merge approval, so this remains a
  hardening ask, not an active exploit.
- Recommended: move `head.ref` through `env: BRANCH: ${{ ... }}` then
  read as `$BRANCH` in the `run:` block. Same pattern
  `agent-factory.yml:144-150` already uses for `RAW_TASK_PROMPT`.

## Recommendations

Priority order (lowest blast radius first, biggest risk reduction):

1. **Fix `--yolo` deny-list** (C1). Replace `matchesPattern` with
   `micromatch`/`minimatch` at `nocase: true`, and extend the exclude
   list (`.pem`, `.key`, `AICORE_SERVICE_KEY*`, `.aws/`, `.kube/`,
   `.docker/config.json`, `NPM_TOKEN*`, `GH_PAT*`). Add regression tests
   in `allow-everything.test.ts`. Scope: `fix(core)`.
2. **Apply `overrides` for `image-size`, `uuid`, nested `js-yaml`**
   (W1). Do NOT run `npm audit fix --force` -- it would attempt
   `pptxgenjs@1.1.5` / `node-notifier@6.0.0` downgrades. Validate
   `marked@15.x` preserved. Run the full CI gate locally.
   Scope: `chore(deps)`.
3. **Harden `release.yml`** (W4) -- add `--ignore-scripts` to
   `npm ci` and `npm publish` in the `publish-npm` job, remove
   `continue-on-error: true` from the publish step.
   Scope: `ci(ci)`.
4. **Fix or delete `ExternalDirectoryPermission`** (W3). Either replace
   the `startsWith()` body with `containsPath()` (drop the
   `.toLowerCase()`), OR delete the module if no live caller depends
   on it. Add tests for prefix bypass and case sensitivity.
   Scope: `fix(core)` or `refactor(core)`.
5. **Path-scope `image_gen.outputPath`** (W5). Add
   `containsPath(cwd, outputDir)` before `fs.mkdir`. Reject non-`https:`
   URL schemes at the tool boundary.
   Scope: `fix(tools)`.
6. **Harden `on-release-merge.yml`** (W6) -- move `head.ref` through
   env before shell substitution.
   Scope: `ci(ci)`.
7. **Replace or gate `xlsx`** (C2). Track as a `security`-labelled
   issue; needs `role-architecture` input on the `read` tool office-
   document API.
   Scope: `security` issue, then `feat(tools)` PR.
