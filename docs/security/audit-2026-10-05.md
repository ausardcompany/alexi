## Critical (block)

### C1 -- `--yolo` deny-list bypass: case sensitivity + missing dot-escape + no keyword coverage (UNRESOLVED CARRY-OVER, week 6 - ESCALATION)

- Files:
  - `src/permission/allow-everything.ts:53-56` -- `matchesPattern()`
    naive glob-to-regex converter (verbatim unchanged from 2026-05-25
    commit `099dfc63`; last touch on the file is a style-only
    auto-fix `b564a717`).
  - `src/permission/index.ts:375-393` -- `getAllowEverythingDelegate()`
    seeds excludes from the `deny-secrets` rule.
  - `src/permission/index.ts:387` -- belt-and-braces still only
    appends `**/.ssh/**`, `~/.ssh/**`. No SAP token coverage.
- Bug (unchanged for five consecutive audits): `matchesPattern` does
  `new RegExp(pattern.replace(/\*/g, '.*'))`. This is case-sensitive by
  default, does not anchor with `^` / `$`, and does not escape the `.`
  metacharacter. On Linux (the `alexi-bot` runtime) this produces
  three bypasses in `--yolo` mode:
  1. Case-only variants of `**/.env` (`.ENV`, `.Env`) do not match.
  2. The pattern `**/.env.*` expands to `.*/.env..*` (unescaped dot),
     which still does NOT match `foo.env` -- a co-located `env.json` /
     `dev.env.local` variant slips through if renamed.
  3. `**/*credential*` / `**/*secret*` are literal substring keywords
     only -- they miss `AICORE_SERVICE_KEY*`, `ghp_*` / `github_pat_*`,
     `NPM_TOKEN`, and `SAP_PROXY_*`. The belt-and-braces `**/.ssh/**`
     at `src/permission/index.ts:387` catches SSH keys, but there is
     no equivalent for the SAP token family.
- Severity: `block`. `--yolo` is opt-in on the CLI but is wired into
  agent workflows via `--auto` / `--dangerously-skip-permissions`
  (referenced from `AGENTS.md` under "Tool harness"). A prompt
  injection that convinces the agent to read `AICORE_SERVICE_KEY.json`
  in `--yolo` mode will succeed today. The 2026-09-21 audit escalated
  this to critical; it is still critical.
- Recommended fix (unchanged; owner: `role-security` +
  `role-engineering`):
  1. In `src/permission/allow-everything.ts:53-56`, replace
     `new RegExp(pattern.replace(/\*/g, '.*'))` with `matchPattern`
     from `src/permission/wildcard.ts` (which handles `**`, escaping,
     and anchoring) OR reuse `matchesPattern` from
     `src/permission/next.ts:2`. Do NOT re-implement glob-to-regex a
     fifth time.
  2. In `src/permission/index.ts:375-393` extend the belt-and-braces
     block to add `AICORE_SERVICE_KEY*`, `SAP_PROXY_*`, `NPM_TOKEN*`,
     `GH_PAT*`, `**/*.pem`, `**/*.key`.
  3. Add regression tests to `src/permission/allow-everything.test.ts`
     covering case-only variants, `foo.env`,
     `AICORE_SERVICE_KEY.local`, and a `.PEM` file. (The file already
     exists -- confirmed at `src/permission/allow-everything.test.ts:1`
     -- and currently only exercises the `auto` mode toggle, not the
     deny-list glob logic.)

### C2 -- `xlsx@0.18.5` prototype pollution + ReDoS, no upstream fix (RUNTIME REACHABLE)

- Advisories via `npm audit`:
  - `Prototype Pollution in sheetJS` (`GHSA-4r6h-8v6p-xvw6`, CVSS 7.8).
  - `SheetJS Regular Expression Denial of Service (ReDoS)`
    (`GHSA-5pgg-2g8v-p4x9`, CVSS 7.5).
- `range: "*"`, `fixAvailable: true` (npm advertises a drop that
  leaves `read-office` broken). SheetJS has moved fixes to a paid-only
  distribution channel (`https://cdn.sheetjs.com/`).
- **Change since last audit**: previous audits said "no `src/`
  consumer imports xlsx". This is NO LONGER TRUE. The file
  `src/tool/tools/read-office.ts` (committed 2026-05-30, commit
  `b467571e`) was overlooked in prior scans. Lines 113-121 dynamically
  import `xlsx` and call `xlsx.readFile(filePath, { cellDates: true })`
  on user-supplied paths that reach the `read` tool. This means:
  - A malicious `.xlsx` committed to a repo under read permission can
    trigger either CVE on the agent runner.
  - The dynamic import keeps the attack surface present even if the
    tool is not currently invoked, because `npm ci` installs the
    vulnerable copy.
- Severity: `block`. The reachability change promotes this from
  "unused direct dep" to an actively exploitable path on untrusted
  input.
- Recommended fix (owner: `role-engineering`, up from
  `role-security`):
  - Short term: at `src/tool/tools/read-office.ts:113-121`, guard the
    `xlsx.readFile` call with a size cap and a confirmation path from
    `src/permission/`. The prototype-pollution CVE still fires on
    small inputs, so a size cap alone is insufficient.
  - Preferred: replace with `exceljs@^4.4.0` (active security channel,
    similar `readFile` + `getWorksheet(idx).eachRow` API). The
    `read-office.ts` call site reads only cells, so the migration
    surface is small.
  - Fallback: feature-flag `.xlsx` extraction off by default in
    `isOfficeDocument()` at `src/tool/tools/read-office.ts:36` until
    `exceljs` lands.
