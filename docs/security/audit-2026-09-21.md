## Critical (block)

### C1 -- `--yolo` deny-list bypass: case sensitivity + missing dot-escape + no keyword coverage (UNRESOLVED CARRY-OVER)

- Files:
  - `src/permission/allow-everything.ts:53-56` -- `matchesPattern()`
    naive glob-to-regex converter.
  - `src/permission/index.ts:375-393` -- `getAllowEverythingDelegate()`
    that seeds excludes from the `deny-secrets` rule.
- Bug (unchanged since 2026-08-24 audit): `matchesPattern` does
  `new RegExp(pattern.replace(/\*/g, '.*'))`. This is case-sensitive by
  default, does not anchor with `^` / `$`, and does not escape the `.`
  metacharacter. On Linux (the actual runtime for `alexi-bot`) this
  produces three bypasses in `--yolo` mode:
  1. Case-only variants of `**/.env` (`.ENV`, `.Env`) do not match the
     regex because `.env` literally maps to `.*/.env` case-sensitively.
     A tool run in `--yolo` mode can therefore read a file literally
     named `.ENV` in a case-preserving filesystem.
  2. The pattern `**/.env.*` expands to `.*/.env..*` (unescaped dot),
     which matches `.envXlocal` -- a benign false-positive, but also
     matches nothing that ends in `.env` (e.g. `foo.env`) unless a
     literal dot follows.
  3. `**/*credential*` / `**/*secret*` are literal substring keywords
     only -- they miss the SAP-specific token `AICORE_SERVICE_KEY*`
     (uppercase, no `credential` or `secret` substring). The
     belt-and-braces `**/.ssh/**` clause in
     `src/permission/index.ts:387` correctly catches SSH, but there is
     no equivalent belt-and-braces for `AICORE_SERVICE_KEY`,
     `SAP_PROXY_*`, `GH_PAT`, or `NPM_TOKEN`.
- Severity: `block`. `--yolo` is opt-in on the CLI but is wired into
  agent workflows (`agent.ts:83, 131`, `chat.ts:172, 231`). A prompt
  injection that convinces the agent to read `AICORE_SERVICE_KEY.json`
  will succeed in `--yolo` mode today.
- Recommended fix (unchanged from 2026-08-24 recommendation):
  1. In `src/permission/allow-everything.ts:53-56`, replace
     `new RegExp(pattern.replace(/\*/g, '.*'))` with a proper
     glob-to-regex that (a) escapes regex metacharacters other than
     `*`, (b) anchors with `^` and `$`, (c) sets the `i` flag, and (d)
     handles `**` distinctly from `*` (or, better, delegates to the
     existing `wildcard.ts` matcher already used by the main
     permission engine).
  2. In `src/permission/index.ts:387`, expand the belt-and-braces
     exclude list to include `**/AICORE_SERVICE_KEY*`,
     `**/GH_PAT*`, `**/NPM_TOKEN*`, `**/SAP_PROXY_*`, `**/.aws/**`,
     `**/.kube/**`, `**/.pem`, `**/.key`.
  3. Add a regression test in `src/permission/allow-everything.test.ts`
     that asserts every pattern in `deny-secrets` is denied in each of
     lowercase, uppercase, and mixed case.

### C2 -- `xlsx@0.18.5` (SheetJS) prototype pollution and ReDoS, no upstream fix (UNRESOLVED CARRY-OVER)

- Package: `xlsx@0.18.5` (direct dependency, `package.json`).
- Advisories:
  - `GHSA-4r6h-8v6p-xvw6` -- Prototype Pollution in sheetJS (`CWE-1321`).
  - `GHSA-5pgg-2g8v-p4x9` -- SheetJS ReDoS (`CWE-1333`).
- `npm audit` reports `fixAvailable: false` -- the maintainer (SheetJS)
  moved the fix to a paid CDN release and did not publish the patched
  version to npm.
- Usage: `src/tool/tools/read-office.ts:113-131` dynamically imports
  `xlsx` and calls `readFile(filePath, { cellDates: true })` and
  `sheet_to_csv(ws)` on any file with extension `.xlsx` or `.xlsm`.
  The input is a filesystem path picked by the agent, so an
  adversarial spreadsheet placed on disk (e.g. by a prior tool call or
  MCP server) can trigger both advisories.
- Severity: `block` if the read-office tool is ever surfaced to
  untrusted input. Today, `read-office` is behind the standard
  permission gate for filesystem reads, which mitigates *external*
  attackers but does not mitigate prompt-injection-via-MCP.
- Recommended action:
  1. Migrate `read-office.ts:113-131` to the maintained
     `@sheet/core` fork or to `exceljs`, both of which are on npm and
     have current CVE fixes.
  2. If migration is deferred, add an explicit `.xlsm` denylist in
     `isOfficeDocument()` (`src/tool/tools/read-office.ts:36-42`) --
     macro-enabled workbooks are the highest-risk shape and their
     removal is a one-line change.
  3. Document the deferred CVE in a top-level `SECURITY.md` and add a
     workflow-level suppression note pointing at this section.

## High (warn)

### H1 -- `pptxgenjs@4.0.1` transitively pulls vulnerable `image-size@1.2.1` (fix requires major bump)

- `image-size` advisories:
  - `image-size: ICNS parser allows denial of service through an
    infinite loop` (`CWE-835`).
  - `image-size: JXL and HEIF parsers allow denial of service through
    infinite loops` (`CWE-835`).
- `fixAvailable: { name: "pptxgenjs", version: "2.2.0", isSemVerMajor: true }`
  -- the "fix" is a **downgrade** major (4.x -> 2.x), which is a
  breaking change that would strip the modern PPTX APIs. Do not run
  `npm audit fix --force`.
- Usage: no direct import of `pptxgenjs` was found in `src/`
  (`grep -rn "pptxgenjs" src/` returns zero hits). If `pptxgenjs` is
  not consumed by any code path, it is an unused dependency and should
  be removed from `package.json` outright.
- Severity: `warn` (DoS only, not RCE; no direct consumer found).
- Recommended action: audit whether `pptxgenjs` is dead weight in
  `package.json`. If it is used by a plugin or template not currently
  in `src/`, pin a hardened upstream (`pptxgenjs@^4` requires `image-size@>=1.3` which upstream has not published; a maintainer
  ping is in order).

### H2 -- `node-notifier@10.0.1` pulls vulnerable `uuid@8.3.2`

- `uuid` advisory: `uuid: Missing buffer bounds check in v3/v5/v6 when
  buf is provided` (`CWE-787,CWE-1285`).
- `fixAvailable: { name: "node-notifier", version: "6.0.0", isSemVerMajor: true }`
  -- again a downgrade major. Do not auto-apply.
- Usage: `src/core/notifications.ts` uses `notify({ title, message })`
  only. The v8 UUID buffer-overflow requires the caller to pass a
  `buf` argument, which our code never does. Runtime exposure is
  therefore zero, but `npm audit` will keep flagging it.
- Severity: `warn` (not exploitable via our code path).
- Recommended action: add an audit exception with justification, or
  pin `uuid@>=11` via `overrides` in `package.json` -- the latter is
  the cleaner fix and does not require a `pptxgenjs`-style downgrade.

### H3 -- `js-yaml` and `@xmldom/xmldom` transitive DoS (fix available, needs `npm update`)

- Findings (both from `npm audit --omit=dev`):
  - `js-yaml@4.3.1` (via `cosmiconfig`) -- CVE-2026-59870 (quadratic
    CPU consumption in `!!omap` resolution) and merge-key CPU DoS.
    `fixAvailable: true`, transitive.
  - Nested `gray-matter/node_modules/js-yaml@3.15.0` -- same class of
    findings.
  - `@xmldom/xmldom@0.8.13` and nested `plist/node_modules/@xmldom/xmldom@0.9.10`
    -- 12 distinct advisories including ReDoS, quadratic-memory
    consumption, and multiple `requireWellFormed` bypasses.
    `fixAvailable: true`, transitive.
- Severity: `warn` -- exploitation requires attacker-controlled YAML
  or XML input. Alexi parses:
  - YAML: only its own workflow files (`.github/workflows/*.yml`) at
    dev time, and `mcp-servers.json` (JSON, not YAML). No untrusted
    YAML on the runtime path.
  - XML: only via `plist` (Apple property lists), which is only used
    if `pptxgenjs` is used (see H1).
- Recommended action: run `npm update js-yaml @xmldom/xmldom
  gray-matter plist` and re-run `npm audit`. If Dependabot has an open
  PR for these, prefer merging that PR (none open as of this scan --
  see I2).

### H4 -- `.github/workflows/security.yml` audit gate is toothless

- File: `.github/workflows/security.yml:12-25`.
- Bug: `npm audit --audit-level=high` runs with `continue-on-error:
  true`. The weekly job therefore prints the finding count but always
  passes green, so the branch-protection signal is meaningless and the
  H3-class findings above went unblocked.
- Severity: `warn`. This is a CI hygiene finding, not a code CVE, but
  it directly explains why C2 and H1--H3 have accumulated.
- Recommended fix: remove `continue-on-error: true` on the `npm audit`
  step (line 25) and pin the audit threshold at `--audit-level=critical`
  so the job fails only on critical findings. Documented exceptions
  (C2, H1, H2) can then be added via `.npmrc`'s `audit-ignore-registry`
  or `npm audit --json | jq` filtering.

### H5 -- `release.yml` still calls `npm ci` without `--ignore-scripts` (UNRESOLVED CARRY-OVER from 2026-06-22 W4)

- File: `.github/workflows/release.yml` (unchanged since 2026-08-24
  audit). The release pipeline runs `npm ci` in a fresh runner that
  has publish credentials mounted, and does not pass `--ignore-scripts`.
- Attack: a malicious `postinstall` script in any transitive
  dependency would execute inside the release runner with access to
  `NPM_TOKEN` and `GH_PAT`.
- Severity: `warn` -- lockfile drift is monitored by encoding-guard
  and by daily-merge, but this remains a documented residual risk.
- Recommended fix: add `--ignore-scripts` to the `npm ci` step in
  `release.yml`, and if any dependency's build step is required,
  pin it explicitly. Also consider migrating to
  `actions/setup-node@v4`'s `cache: npm` with a lockfile checksum.
